## Сценарии браузерных проверок

- Реальная форма предупреждения: выбор участника, причина, POST, поиск сохранённого дела, отмена и подтверждение в API.
- Включение/отключение Shield и сохранение чувствительности с проверкой серверного состояния.
- Предпросмотр Studio без побочных эффектов, сохранение сценария, его выключение и чтение через API.
- Сохранение настроек и повторный вход на страницу с тем же значением.
- Все восемь разделов на ширинах **320, 360, 375, 390, 430, 768, 1440 px**. Проверяются реальные размеры DOM после загрузки данных.
- Явно смоделированные `503` и повтор запроса, `403` без административных переключателей. HTTP 200 со статусом дела `unknown` не должен показываться как успех создания или отмены наказания.
- Загрузка artwork, выбор дня клавиатурой, доступная таблица данных и положение последнего действия относительно мобильной панели.

## Что работает с настоящим backend

Demo-вход выдаёт настоящую серверную сессию. Dashboard, участники, дела модерации, настройки Shield, Studio и preview, аналитика, апелляции и настройки чата получают ответы FastAPI и используют выбранную SQL-базу. Изменения форм сохраняются. Начальный чат, участники и история в demo — **синтетические данные**; Telegram gateway явно демонстрационный.

Production-adapter Telegram реализован и проверяется контролируемыми ответами Bot API. Успешный mock-тест не доказывает подключение настоящего бота. AI-provider отключён; Intelligence показывает эвристические сигналы для ручного разбора.

## Сохранённые проверки инфраструктуры и API

Следующие проверки выполнены **16 октября 2026** и не выдаются за повторные измерения после изменения дизайна:

- Чистая PostgreSQL-база доведена миграциями до `83cf61c29d3a`, `alembic check` не выявил расхождений. В этой итерации схема не менялась.
- Dump восстановлен в отдельную проверочную БД: **1 чат, 8 пользователей, 4 дела**. Production PITR и внешнее backup-хранилище не проверены.
- Python runtime `pip-audit`: **No known vulnerabilities found** для lockfile.
- HTTP benchmark: **300/300** успешных ответов, p95 **240,442 мс**, бюджет 300 мс выполнен. Один Uvicorn worker, PostgreSQL, десять клиентов, повышенный лимит API. Это локальный результат, без production throughput и реального Telegram. Данные: [benchmark-final.json](benchmark-final.json); ранний замер под параллельными сборками p95 370 мс: [benchmark-local.json](benchmark-local.json).

## Что проверяет backend

Unit/API/bot-тесты проверяют подпись и срок `initData`, запрет повторного обмена, срок сессии, chat-scoped RBAC, права, idempotency, сроки наказаний, отмену, предупреждения и эскалацию. Есть проверки ошибок и неоднозначных ответов Telegram, rate limiting, webhook, durable receipt до подтверждения updates, повторных событий, поддерживаемых правил Studio и очистки payload.

Интеграционные тесты используют настоящие PostgreSQL row locks и Redis: конкурентные наказания и отмены, пересекающиеся ограничения, конфликт ключа идемпотентности, потерю прав, replay guard и атомарные Shield-счётчики. Для PostgreSQL создаются отдельные случайные схемы; существующие таблицы не очищаются.

Без `NOX_TEST_POSTGRES_URL` и `NOX_TEST_REDIS_URL` соответствующие проверки пропускаются. Такой запуск не доказывает работу PostgreSQL или Redis. Инфраструктура тестов должна быть отдельной от production.

## Что ещё не проверено или не завершено

- Настоящий bot token, внешний webhook HTTPS, наказание в тестовой супергруппе и ограничения настоящего Telegram Bot API. Имя/username зарегистрированного Telegram-бота задаются владельцем через BotFather при подключении.
- Mini App в реальных Telegram Android/iOS, safe area клиента, клавиатура, сворачивание/разворачивание, BackButton, haptic feedback и истечение сессии в клиенте.
- Production-домен, TLS, независимое хранение секретов, внешние мониторинг/alerting, длительная нагрузка, большой объём данных и несколько процессов в эксплуатационном окружении.
- Автоматический Emergency Mode с восстановлением прав; полная Anti-Raid-система. Сигналы вступлений сами по себе не меняют права группы.
- AI-provider, качество контекстных решений, бюджет передачи данных; планировщик и дополнительные пары trigger/action Studio; Universe и транзакционная экономика.
- Выбор лицензии владельцем. Отсутствие `LICENSE` не даёт разрешение на свободное распространение.

Команды запуска и тестов: [development.md](development.md). Автоматический deployment в production не включён. Изменение GitHub About текущая интеграция ранее отклонила с HTTP 403; отправка исходников и GitHub Actions доступны.
